01 · Purpose and status

Executive overview & V1 status

Hagere empowers Ethiopian civic engagement by making public policies easier to discover, understand, and discuss. The platform brings policy documents, public discussion, and policy-related news into one accessible civic space.

Version 1 platform

Node.js and Express serve the static frontend and REST API; MongoDB Atlas stores platform data; Firebase Authentication supports user identity; and Gemini powers policy-document question answering from direct PDF URLs.

Verification

The V1 baseline was 61/61 tests passing; the latest verification on this checkout passed 63/63. Run npm test after changes for the current result.

02 · System design

Technical architecture & data flow

Client and server

Express serves static HTML, CSS, and JavaScript from public/. Browser pages call RESTful Express routes, which validate requests, enforce role-based authorization where required, and read or update MongoDB through Mongoose.

AI policy assistant (RAG)

The policy chat endpoint loads the policy's direct, publicly reachable HTTP or HTTPS PDF URL, sends its content and the user's prompt to the Gemini API, and returns an Amharic answer grounded in the document. The URL must not redirect or resolve to private network addresses. HTTPS certificate verification remains enabled; configure trusted certificate authorities rather than bypassing TLS validation. The current implementation uses gemini-3.1-flash-lite with bounded document downloads and request timeouts.

Database and seed data

Mongoose models represent Policy, News, and User records. The seed scripts use repeatable upserts and retry transient MongoDB Atlas DNS SRV and connection failures.

03 · Repository map

Project directory & codebase structure

All request-handling modules are consolidated under controllers/. Environment and integration helpers live in utils/.

├── controllers/      # Policy, news, auth, chat, analytics, and rate-limit handlers

├── models/           # Mongoose schemas (Policy, News, User)
├── public/           # HTML, browser JavaScript, and shared styles/assets
├── routes/           # Express REST API routes

├── test/             # Node test-runner unit and asset tests

├── utils/            # Environment and application helpers
└── server.js         # Express app and route initialization

API endpoint reference

Method Endpoint Purpose and access
GET/api/policiesList policies; public access, optional authenticated context.
POST/api/policies/:id/chatAsk the AI assistant about a policy document.
GET/api/newsRead the news feed; public access.
POST/api/news/:id/likeToggle a citizen's like on a news item; citizen authentication required.

DELETE/api/policies/:idDelete a policy; admin authentication required.

Authenticated calls use the Firebase ID token in the Authorization: Bearer <token> header. Request bodies should be JSON where applicable.

05 · Operations

Deployment & environment operations

  1. Create a Render Web Service. Connect the repository, use the Node runtime, set the build command to npm install, and the start command to npm start. Configure the service to use the repository's Node.js version and monitor deploy logs and health.
  2. Configure environment variables. The app currently reads CONNECTION_STRING for MongoDB (not MONGODB_URI), plus PORT, NODE_ENV, GEMINI_API_KEY, FIREBASE_API, SERVICE_ACCOUNT, ADMIN_FIREBASE_PROJECT_ID, ADMIN_SERVICE_ACCOUNT, and ADMIN_UIDS. Store credentials only in the hosting provider's secret environment settings, never in source control.
  3. Set up MongoDB Atlas access. Create a database user with only the permissions the app needs, set CONNECTION_STRING to its SRV connection string, and allow the Render service's outbound IP addresses in Atlas Network Access. Avoid broad public IP access in production.
  4. Configure Firebase Authentication. Enable the sign-in providers used by the app and add the deployed Render hostname to Firebase Authentication's Authorized domains. Ensure the client Firebase configuration and server service-account credentials belong to their intended projects; configure the admin project and allowlisted admin UIDs separately.
  5. Verify the deployment. Confirm the service starts, static pages load, database connection succeeds, authentication callbacks return to an authorized domain, and policy chat has a valid Gemini API key. Run npm test before deploying changes.

Environment variable names above follow the current application configuration. Firebase web API configuration is not a substitute for protecting server credentials; never publish service-account private keys.
